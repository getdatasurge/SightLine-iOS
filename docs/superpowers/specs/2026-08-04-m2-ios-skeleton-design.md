# SightLine Field — M2 iOS Skeleton Design

Date: 2026-08-04
Status: Approved (user, this session)
Repo: `getdatasurge/SightLine-iOS` (`main`)
Upstream context: `SIGHTLINE-FIELD-APP-BRIEF.md` in the SightLine web repo (W27), ADR-0010 (M1 mobile-auth backend, merged on web repo `integration/field-app`).

## Goal

A buildable, runnable iOS app skeleton plus project outline for the SightLine field/installer app. Login works against the live M1 `/api/v1/auth/*` endpoints; all data screens are compiling shells with empty states until the M2 backend read endpoints exist. This repo houses M2–M5 of the brief's milestone plan.

## Decisions (locked)

| Decision | Choice |
|---|---|
| Project definition | XcodeGen `project.yml`; `.xcodeproj` gitignored |
| Minimum iOS | 17.0 (SwiftData, `@Observable`, modern BackgroundTasks) |
| UI | SwiftUI only; no UIKit unless camera/scan forces it (M5 question) |
| Local store | SwiftData |
| API client | Apple `swift-openapi-generator` (SPM build plugin) over a committed spec snapshot `openapi/openapi.json`; no hand-written networking outside the transport/auth-middleware seam |
| Secrets | Keychain, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`; never UserDefaults |
| Bundle id / name | `com.getdatasurge.sightline.field` / "SightLine Field" |
| Scaffold scope | Buildable skeleton + outline docs; no backend work, no sync engine, no capture |

## Components

### Core/Auth
- `KeychainTokenStore`: stores access + refresh token (`slm_…` opaque pair) under `AfterFirstUnlockThisDeviceOnly`; get/set/clear; unit-tested against simulator keychain.
- `SessionManager` (`@Observable`): state machine `signedOut → authenticating → signedIn(AccountContext)`. Login calls `POST /auth/login` with device metadata (name, model, OS, app version); stores pair; loads `GET /auth/me` (account, business, technicianId, capabilities). On any 401: one `POST /auth/refresh` (rotating, one-time-use per ADR-0010), retry once; refresh failure → clear keychain → signedOut. Logout calls `POST /auth/logout`, clears local state regardless of network outcome.

### Core/ApiClient
- Generated by swift-openapi-generator from `openapi/openapi.json`. Middleware injects `Authorization: Bearer`, performs the single-refresh-then-retry dance via `SessionManager`.
- Spec provenance: fetched from a server running the M1 branch (local dev stack). Regenerated at each milestone's API change; spec committed so a server deploy can't silently break a shipped binary.

### Core/Store
- SwiftData `ModelContainer` with the synced-subset models plus `SyncOutbox` (`clientUuid`, endpoint, payload, attempts, lastError, state ∈ pending/inFlight/conflict/done). Schema only in this pass — the sync worker is M4.
- Layering rule enforced now: views read only the local store; the network layer writes into the store. Nothing in the UI awaits a request (PP.10 "immediately usable").

### Core/Config
- `AppEnvironment`: Debug default `http://localhost:3000`, overridable (launch arg / settings); Release placeholder for the staging host (brief decision 5-adjacent — staging host TBD, does not block the skeleton).

### Features
- `Login`: email/password + device registration; error surface for bad credentials / no membership.
- `Schedule`, `Jobs`, `WorkLogs`: navigation shells with typed view models reading the (empty) store; explicit empty-state views labeled "awaiting M2 sync". No fake data.

## Error handling
- Typed `ApiError` (network / 401-after-refresh / 4xx envelope / 5xx) mapped at the middleware seam; views render empty/error states, never crash on offline.
- 401-after-refresh always terminates the session (theft-signal semantics from ADR-0010 rotation).

## Testing
- Unit: `KeychainTokenStore` round-trip, `SessionManager` transitions (login success/failure, refresh rotation, refresh-replay logout), `AppEnvironment` resolution. Pure Swift, deterministic.
- Smoke: build + run in simulator; login against local dev stack running the M1 branch.
- CI: GitHub Actions macOS runner — xcodegen, `xcodebuild build test` on iPhone simulator, on every PR. No signing/TestFlight yet (Apple Developer account ownership unresolved — brief decision 5).

## Out of scope
- Backend v1 read endpoints (M2 backend work, lives in the web repo).
- Sync engine / outbox replay (M4), offline capture (M5), push notifications (out of v1 per brief), TestFlight distribution.

## Milestone outline (PLAN.md content)
- **M2** — read-only app: backend technician-scoped reads (web repo) + these shells filled in: schedule, job detail, surfaces, delta refresh. DoD: seeded technician signs in, sees today's jobs offline-after-first-sync, no prices without `pricing.view`.
- **M3** — check-in/out writes, online-only; photos; status advance.
- **M4** — offline outbox + sync worker, conflict UX, clock-skew flagging.
- **M5** — offline survey capture port (deferred, own brief).
